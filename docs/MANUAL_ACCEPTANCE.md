# 三角色手动点击验收清单

入口：[MedFlow](http://127.0.0.1:8080/)。使用本轮新镜像，具体构建/验证结果看最新交付报告。此清单用于你亲自测试；没有勾选就不代表你已经掌握。

## 准备与身份

| 用途 | 账号 | 密码 | 对应医生 |
| --- | --- | --- | --- |
| 管理 | admin | 123456 | 不接诊 |
| 默认医生主线 | doctor | 123456 | 演示医生，优先保留你原有绑定；科室通常为演示门诊 |
| 患者 | patient | 123456 | 可管理本人和家属就诊人 |

附加医生只在本地双演示开关开启并成功补齐后存在。账号映射以管理员「医生」表中的登录账号为准；不要给林医生挂号，却用doctor账号找他的预约。

建议三个独立浏览器会话，或每轮点右上角「退出」后换角色。同一站点同一个浏览器会话共享令牌。只用明确虚构姓名，测试备注写“学习验收”。

记下本轮自己的：日期____、科室____、医生/账号____、就诊人____、预约编号____、接诊编号____。日期用页面实际日期，不照抄固定ID或旧截图。

## A. 管理员准备

- [ ] A1 admin登录→「医生」→选择演示门诊。预期看到“演示医生”和登录账号doctor的绑定。
- [ ] A2 点「维护资料」→核对姓名/职称/擅长/简介→把简介追加“【学习验收】”并保存。预期成功后重新打开仍存在。
- [ ] A3 退出换patient→找同一医生，确认新简介可见。此步骤验证管理写入与患者读取相连，不只是弹窗显示成功。
- [ ] A4 回admin→「排班与发布」查看未来7天PUBLISHED和更后一天DRAFT，打开详情看诊室/时段/余量。
- [ ] A5 用未使用的未来日期/医生/诊室创建一场学习草稿并发布。记录日期与医生，给患者主线使用。医生与诊室须同科室，已有重叠会拒绝。
- [ ] A6 找无有效预约的未来排班练习取消出诊；有有效预约的排班应拒绝取消，不能自动把患者约退掉。
- [ ] A7 「门诊工作台」点补齐演示数据。已经完成或取消的业务不能变回初始状态，已有简介不能被默认简介覆盖。

## B. 患者按真实路径预约

- [ ] B1 patient登录→「预约号源」。预期先看到“按科室预约 / 找医生预约”及科室卡片，不直接铺全院时间卡片。
- [ ] B2 点演示门诊→阅读演示医生职称/擅长/简介→选择该医生。预期出现日期和上午/下午的时段。默认明日，可更改。
- [ ] B3 换一个科室，再换医生/日期。旧医生的时段不得残留；无号应有换日期/换医生的入口。
- [ ] B4 点「找医生预约」搜索“林”或“皮肤”，可按科室筛；进入医生资料和日期，不必先找到一张全院号源卡片。
- [ ] B5 回到doctor对应的演示医生，选有余号时段→预约→选择一个虚构就诊人→核对医生/科室/日期/时间后提交。
- [ ] B6 预期创建成功、显示预约编号/确认截止；点「立即确认」。这是患者确认，不等管理员审批。
- [ ] B7 「我的预约」能看到已预约状态。打开详情，创建/确认时间线各有一次；重新查看不能重复扣号。
- [ ] B8 另建一笔可取消的预约→截止前取消→重新查时段。预期仅回补一次；刷新后仍是已取消，可以按规则重新预约。
- [ ] B9 对明日预约尝试查看签到条件：今天不能签到，这是正常规则。不能为“让测试过”修改系统时间或放宽后端。
- [ ] B10 到真实预约当天，在时段开始前30分钟至结束前，点该预约「就诊与病历」→确认到院签到。预期出现待就诊；重复签到仍是同一接诊编号。

夜间测试可先完成B1–B9。B10需要实际时间窗口；今日已签到虚构示例供C部分练习，不代表你本人已手动跑过签到。未来7天的上午门诊让你下次能按正常窗口验证。

## C. 医生接诊与患者回看

- [ ] C1 doctor登录→「我的排班」，能找到你给演示医生安排的班；医生无需报名或认领。
- [ ] C2 「预约患者」日期改为B部分所约日期，能找到该预约。默认查今天，明日预约不会在今天列表显示。
- [ ] C3 「候诊与接诊」查今天，选尚未处理的“演示·候诊…”；若你已处理过，切换其他记录或等待新日期补齐，不期待刷新把完成状态重置。
- [ ] C4 先点“演示·候诊一（虚构）”姓名/档案入口，查两个过去日期：林医生、周医生的病历与处方。即使该患者当前接诊已完成，历史仍应只读可看。
- [ ] C5 返回队列→打开一条WAITING→开始接诊。预期变为就诊中；有另一位就诊中时，应先处理完成。
- [ ] C6 写主诉、现病史、诊断、医嘱，先不保存点查看历史。预期提示先保存，不静默丢失输入。
- [ ] C7 保存草稿→打开历史→点返回本次接诊，仍能看到已存内容并继续。记录版本变化。
- [ ] C8 可选：处方与收费→选启用的演示药、数量和用法→保存→核对金额→提交。若留着处方草稿，完成接诊应被拒绝，先提交或放弃。
- [ ] C9 完成接诊。预期病历只读，队列显示已完成，不能再改正文或取消这次已签到预约。
- [ ] C10 换patient→该就诊人档案→本次记录，核对四项正文、医生和时间线；完成之前不应看到草稿。
- [ ] C11 可选：患者处方与缴费→待缴费→确认模拟缴费。预期状态更新，重复操作无第二笔支付，无真实扣款。

## D. 纵向档案与异常

- [ ] D1 patient→「就诊人」→点姓名或「查看就诊档案」。同一个人可显示多日期、多医生，不是一人只能一条记录。
- [ ] D2 打开旧记录，核对开具医生、主诉/现病史/诊断/医嘱、药品数量/单价/总额、缴费状态、预约与接诊时间线。
- [ ] D3 返回列表再切换另一位家属。不能继续显示上一个人的病历；无记录时明确空态。
- [ ] D4 医生从本人预约/候诊打开同人档案可读其他医生已完成记录；无法编辑其他医生病历。
- [ ] D5 患者访问医生菜单或医生访问管理接口应被后端拦截。高级接口越权、任意ID猜测和并发用自动化测试验证，不靠前端隐藏按钮证明权限。
- [ ] D6 手机宽度约390查看预约页和历史；长姓名、简介不撑破页面，处方表格可局部横向滑动。
- [ ] D7 临时断网后读页面，确认失败有可重试入口；提交结果不确定先看“我的预约”，不随便换幂等键盲点。

## 每做完一个步骤记录什么

本轮B01–B04仍处于源码阶段，按用户要求没有运行测试或部署。后续编译、迁移和部署完成后，才执行[任务单中的新验收项](SHANGYITONG_ADOPTION_PLAN.md)：统一预约凭证、多种日期余量状态、复诊来源隔离、普通/复诊幂等兼容、改名后快照及旧数据回退。当前旧容器缺少新按钮或接口不作为本轮已部署功能的故障。

用浏览器Network记录：method/路径、请求关键ID、响应code、TraceId；不要复制Bearer/.env密钥。数据库只做本人理解用的只读核对，写入都从页面完成。

失败记录模板：步骤____；账号角色____；日期/医生____；预期____；实际____；业务错误码____；TraceId____；截图____。时间不在窗口、账号不匹配、记录已处理，都先核对规则再报错。

这份清单是你自己的验收任务，不自动替你打勾。项目当前完成/未完成与开发实测证据分别见 [业务台账](BUSINESS_PROGRESS.md)、[本轮测试报告](05-test-report.md)。
