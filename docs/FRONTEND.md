# MedFlow 前端使用与验证

当前Docker已准备完整三角色数据，先读[演示指南](DEMO_DATA_GUIDE.md)，数量和截图见[系统交付](SYSTEM_DEMO_DELIVERY.md)。管理员工作台支持补齐当天数据，医生由管理员分配出诊。

前端位于 `src/main/resources/static/`，使用 HTML、CSS 和原生 JavaScript，无 npm 依赖、无单独构建步骤、无 CDN。Spring Boot 提供首页和 `/assets/` 静态资源，页面通过同源 API 完成管理员排班/药品维护、患者预约签到、医生接诊/病历/处方、患者模拟缴费和业务统计。Maven 打包后，页面随应用 JAR 一同交付。

> 2026-10-20 更新：药品、处方、模拟收费和统计已纳入当前范围；统一状态见 [业务台账](BUSINESS_PROGRESS.md)，规则见 [处方与统计需求](PRESCRIPTION_STATISTICS_REQUIREMENTS.md)，验收见 [新增交付报告](PRESCRIPTION_STATISTICS_DELIVERY.md)。10-19的 [两天交付需求](TWO_DAY_DELIVERY_REQUIREMENTS.md) 和 [学习指南](TWO_DAY_LEARNING_GUIDE.md) 保留预约→接诊→病历主线，其旧“药品/收费/统计尚未纳入”描述由本次更新覆盖。

本文描述当前源码支持的操作；具体环境是否验证通过，以对应日期的验收报告和实际输出为准。

## 访问入口

### 本机运行

按 [README 的本地启动说明](../README.md#环境与本地启动) 准备 JDK 25、MySQL 8.4、数据库和 `MEDFLOW_DB_*`、`MEDFLOW_JWT_SECRET` 环境变量，在项目根目录执行：

```powershell
.\mvnw.cmd package
java -jar .\target\medflow-0.0.1-SNAPSHOT.jar --spring.profiles.active=local --server.address=127.0.0.1 --server.port=8080
```

访问 [MedFlow 首页](http://127.0.0.1:8080/)。直接双击 `index.html` 无法完成接口调用。修改静态资源后，重新打包并重启 JAR；浏览器仍显示旧页面时执行强制刷新。

当前迁移为 V1–V12：V9 接诊/病历表、V10 排班取消信息、V11 药品目录、V12 处方/明细/账单/模拟支付。应用启动时由 Flyway 增量执行；保留旧库，不要手改已执行迁移的校验记录。Docker需重建应用镜像后再启动新版本，不能仅强刷浏览器更新后端。

### Docker 运行

安装并启动 Docker 后，在项目根目录执行：

```powershell
.\docker-start.ps1
```

脚本在全新安装且缺少 `.env` 时生成配置，构建镜像并启动 MySQL 和应用；已有数据卷时必须保留原 `.env`。默认入口是 [MedFlow 首页](http://127.0.0.1:8080/)；若 `.env` 修改了 `MEDFLOW_APP_PORT`，使用对应端口。前后端在同一应用容器中，无需单独启动前端服务。

本机镜像已准备后，日常可双击项目根目录的 `启动MedFlow.cmd`，停止用 `停止MedFlow.cmd`；两者均保留数据库。Docker 的三角色账号和完整操作见 [Docker 使用说明](DOCKER.md)。

## 登录账号与三个角色

Docker 默认的本机演示模式使用下表；登录页会显示对应的三角色快捷填入按钮，点击后仍需提交登录：

| 角色 | 用户名 | 密码 |
| --- | --- | --- |
| 管理员 | `admin` | `123456` |
| 医生 | `doctor` | `123456` |
| 患者 | `patient` | `123456` |

doctor 已绑定医生档案，患者账号仍需建立就诊人记录。该模式通过 `MEDFLOW_DEMO_ACCOUNTS_ENABLED=true` 显式开启，只用于本机 Docker 演示；已有的 admin 密码会调整为 123456。普通非 Docker 安装默认不开启初始化，历史空库迁移账号如下：

| 角色 | 用户名 | 密码 | 主要入口 |
| --- | --- | --- | --- |
| 患者 | `patient.li` | `Patient@123` | 就诊人、预约号源、我的预约、签到与结果、处方与缴费 |
| 管理员 | `admin` | `Admin@123` | 科室、诊室、医生账号与档案、排班、药品目录、业务统计 |
| 医生 | 管理员实际开通的用户名 | 管理员开通时设置的初始密码 | 本人排班/预约、候诊与接诊、病历及处方 |

普通非 Docker 安装如需新的医生账号，由管理员开通后使用当时填写的用户名和密码登录。Docker演示使用已绑定的 `doctor`，不需要再次开通或绑定同名账号。仓库旧迁移中存在 `doctor.wang`，不能据此猜测其当前密码；绑定已有账号也不会重置该账号密码。

账号与业务档案分开：患者登录后仍需建立归属自己的就诊人记录；医生账号需要一份绑定的启用医生档案。一个医生账号只绑定一份医生档案。已修改的旧数据库以其中的实际账号为准。

## 管理员：从资源准备到出诊安排

1. 在「科室」创建或选择科室，在「诊室」为该科室添加诊室。
2. 进入「医生」，选择科室和「开通新账号」，填写用户名、初始密码、姓名。密码至少 8 位，UTF-8 编码不超过 72 字节。账号和医生档案在同一事务中创建；用户名重复不会留下半条档案。已有且知道密码的医生账号可选择「绑定已有账号」。
3. 查看「班次模板」，了解时间范围、时段长度和每段容量。当前页面提供查看，模板由迁移预置。
4. 进入「排班与发布」，点击「创建 / 批量排班」，选择同一科室的医生、诊室、班次和首个未来日期。可再填最多 6 个日期，以逗号或换行分隔；整批为同一套资源，日期不得重复。
5. 创建得到草稿；任意一天医生或诊室时间重叠，整批回滚。创建成功后在服务端目录查询记录，点击「查看详情」，检查时段和容量，再点击「发布并开放预约」。发布后才生成患者可约号源。
6. 目录支持日期范围、科室、医生、状态筛选及分页。记录来自数据库，换浏览器或其他管理员终端创建的排班也能查询。详情展示号源时段、实时余量、有效预约数和取消原因。

草稿详情中的容量按排班保存的班次配置计算，尚未生成真实 Slot，患者不能预约。管理员首页的医生/诊室数量来自各科室资源；某部分读取失败时显示未加载，避免把部分数据误当总量。

### 受限取消出诊

排班详情中展开「取消本次出诊」，填写不超过 200 字的原因。只允许开诊前、且没有 `PENDING_CONFIRMATION` 或 `BOOKED` 预约时取消；取消会记录原因、操作人和数据库时间。已有有效预约时返回冲突，不会自动取消患者预约。重复取消是成功的无副作用操作。

本版本没有“医生停诊后自动通知、退款、改约”流程，也没有“暂停预约但继续接诊”的独立操作。不要把这里的受限取消宣传为完整停诊补偿。

批量排班没有预约创建那样的幂等结果重放。请求超时或断网后，先按日期和医生查询目录，确认是否已创建，再决定是否重新提交。

## 患者：预约、签到和查看结果

1. 登录后查看首页：就诊人数、累计预约、明日可约时段和最近预约。近期待确认数量只统计最近 5 条，不能代表全部待确认预约。
2. 在「就诊人」添加姓名、性别、出生日期、手机号和关系。出生日期早于今天，手机号为 `1` 开头的 11 位数字；列表展示脱敏号码。
3. 在「预约号源」选择科室、医生和日期，或查看全部科室号源。科室和医生选项来自患者只读目录，不需要管理员权限。默认查询明天，也能查询今天未截止的号源；号源展示真实医生、科室、诊室、时段和余量。
4. 选择号源和就诊人提交预约。创建即占用名额，初始为待确认；确认窗口最多 15 分钟，也可能因号源截止更短。在「我的预约」及时确认。
5. 在「我的预约」切换分页或连续加载，查看详情及历史。「签到 / 就诊结果」读取本人预约的真实医生、诊室、日期和时段，不能从编号猜测就诊信息。
6. 预约已确认，并且数据库时间在**就诊当天、该预约时段开始前 30 分钟至时段结束前**，才能点击「确认到院签到」。例如 08:00–08:30 时段，可在同日 07:30（含）至 08:30（不含）签到。按钮仅是提示，提交时后端会重新校验。
7. 签到成功后进入医生候诊队列，患者不能再取消该预约。弹窗会重新读取后端状态，也可主动刷新。医生完成接诊后，患者才能查看主诉、现病史、诊断和医嘱；接诊中的草稿正文不可见。

预约与接诊状态分开：`BOOKED` 表示预订已确认，不代表已经看诊。签到后的待就诊、就诊中、已完成或已过号由 Encounter 记录。完成和过号均不归还已使用/错过的号源容量。

未签到前，待确认或已预约记录可在取消截止前取消；取消后返还容量。超时扫描会关闭未确认预约并归还名额，页面更新可能有短暂延迟。号源余量随其他请求变化，列表显示有余量不保证提交一定成功。

### 预约提交结果不确定时的重试

创建预约使用 `Idempotency-Key`。前端为“当前账号 + 同一就诊人 + 同一号源”保存请求键，超时后再次提交相同组合会继续使用原键，避免重复占号。先到「我的预约」确认结果，再按提示重试。

更换就诊人或号源会使用各自的请求键。后端重放的创建结果可能保留最初的待确认状态，所以前端创建成功后继续读取详情，确认当前状态再清除请求键。详情读取失败时，页面保留已提交提示和请求键。浏览器禁止存储时，同一弹窗内仍可重试，跨刷新或重开弹窗无法保证恢复原键，应优先查询已有预约。

## 医生：本人排班、候诊和病历

1. 使用管理员实际开通的医生账号登录。进入「医生工作台」，查看今日排班总数、待就诊、就诊中和已完成接诊数量。失败的数据显示“—”，不伪造为 0。
2. 在「我的排班」按日期范围和状态查询本人安排、诊室与余量；在「预约患者」查询某日安排给本人的全部预约。
3. 进入「候诊与接诊」，按日期和接诊状态查询或刷新队列。队列按时段开始、签到时间和接诊编号排序。
4. 对待就诊患者点击「查看并接诊」。达到该预约时段开始时间后，才可「开始接诊」；同一医生同时最多一位就诊中患者。前端操作后仍以后端状态为准。
5. 若患者未到，可展开「患者未到？」，勾选确认并标记过号。**过号是本版本的终态**，没有补叫、重新入队或插队操作。
6. 开始接诊后填写主诉、现病史、诊断和医嘱，点击「保存病历草稿」。首次保存请求携带 `version=0`；保存成功返回实际版本，后续保存继续携带该版本。
7. 填写并保存主诉和诊断；如果需要开药，按下一节先提交处方或放弃草稿，再回到接诊记录点击「完成接诊」。有未保存病历时页面会阻止完成；后端还会复核病历、版本、接诊状态以及是否存在未提交处方。完成后病历正文只读，患者可以查看。

两个标签页同时编辑同一病历时，旧版本保存返回 409。页面会保留当前输入并提示冲突；「重新加载记录」将用服务器内容替换本页未保存内容，请先自行核对需要保留的文字。关闭弹窗或刷新页面不会自动保存草稿。

医生身份来自登录 JWT 对应的医生档案，查询和写入均限定本人数据。修改浏览器参数不能选择另一位医生的操作身份；管理员角色也没有病历正文读取入口。

## 药品、处方与模拟缴费

### 管理员维护药品目录

1. 管理员进入「药品目录」，点击「新增药品」，填写编码、名称、规格、计价单位和单价。编码不重复，保存后不可改；单价为 0.01–999999.99 元、最多两位小数，新药品默认启用。
2. 可按关键词和状态搜索、分页查看。点击「编辑」修改名称、规格、单位、价格或启停状态；不物理删除。
3. 编辑提交携带版本号。若另一页面先保存，返回409，页面保留当前输入；先核对需要保留的内容，再「关闭并刷新目录」。
4. 医生只能选择启用药品。停用后不能新增/重新保存该药品，也不能提交仍含该停用药品的草稿；已经提交处方的明细和价格仍保留。

药品目录变价不会自动改写已有处方。每次保存草稿时后端重新读取目录并保存名称/规格/单位/单价快照；提交沿用最后一次已保存的快照。页面展示人民币两位小数，客户端不能指定账单金额。

### 医生保存、提交或放弃处方

1. 在「候诊与接诊」打开本人的就诊中记录，先保存尚未保存的病历，再点击「处方与收费」。无开药需要时不必创建处方。
2. 在启用药品目录搜索并添加药品。每张处方1–20项，药品不能重复，每项数量为1–1000整数，可填最多1000字的用法说明。未保存的数量和说明仅在本页保留，关窗/刷新不会自动保存。
3. 点击「保存处方草稿」，由后端计价。页面显示“上次保存金额”，修改药品或数量后须再次保存并核对，不能把旧金额当作新草稿总价。
4. 勾选“确认已核对药品、数量和已保存金额”，点击「提交处方并生成账单」。处方变为 `ISSUED`，同一事务生成唯一 `UNPAID` 账单，处方此后只读。本版本不提供已提交处方撤销、退款或部分缴费。
5. 若不需要已保存草稿，展开「不需要这份处方？」，勾选后「放弃草稿」。状态变为 `DISCARDED`、明细和金额清空、不生成账单。接诊仍就诊中时可以重新开方，沿用同一处方ID和递增版本，不从版本0重新开始。
6. 旧版本保存/提交返回409时，当前输入保留；「重新加载处方」会舍弃本页未保存修改，操作前请核对。请求超时后先关闭并重新查看状态，不要假设提交失败。
7. 关闭处方弹窗，重新打开接诊记录完成本次就诊。无处方、已提交处方或已放弃草稿均可完成；仍为 `DRAFT` 时后端拒绝完成。患者是否缴费不决定医生能否完成接诊。

一次接诊最多一张处方，一张处方最多一张账单。重复提交已提交处方返回原结果，不生成第二张账单。处方版本、病历版本和接诊版本各自管理，不能混用。

### 患者查看处方与模拟缴费

1. 患者进入「处方与缴费」，查看本人就诊人的已提交处方，点击「查看并模拟缴费」或「查看明细」。未开药、未提交和已放弃的草稿不会在此展示。
2. 核对药品快照、规格、数量、单价、行金额、总额和账单状态。医生提交后即能看到处方，不必等接诊完成；病历正文仍需医生完成接诊才可见。
3. 对待缴费账单，勾选“确认登记本次模拟缴费，无实际扣款”，点击「确认模拟缴费」。成功后显示 `PAID` 和登记时间。
4. 超时或结果不确定时先「刷新账单状态」。后端仅允许本人操作并防止重复登记，同一账单重复请求不会产生第二条模拟支付记录。

**模拟缴费不会实际扣款，不连接银行卡、微信/支付宝或医保，不代表真实医疗结算。** 本版本没有库存扣减、药房发药、部分支付、退款及多处方合并结算。

## 管理员查看三张业务统计图

进入「业务统计」，默认查询含今天的近7天；可选择起止日期，最多包含93天，点击「查询统计」。每张图下提供完整数据表；横条图最多展示前10项，完整明细仍在表中。空数据明确显示0或无记录，加载失败显示错误，不将失败伪装为0。

| 图表 | 统计口径 |
| --- | --- |
| 预约趋势 | 按预约 `created_at` 日期统计所有创建记录，后来取消/过期仍计入；没有创建记录的日期补0 |
| 科室就诊量 | 只统计 `COMPLETED` 接诊，按 `completed_at` 归属日期 |
| 医生工作量 | 只统计 `COMPLETED` 接诊，按 `completed_at` 归属日期，并展示所属科室 |

统计日期查询含起止两天；后端转换为“开始日00:00（含）至结束次日00:00（不含）”。`BOOKED`、签到和就诊中人数不能作为已完成就诊量；处方已提交、是否模拟缴费也不改变完成接诊统计口径。

## 功能边界与常见错误

| 范围 / 现象 | 当前行为或处理 |
| --- | --- |
| 登录有效期 | 默认 30 分钟；没有注册、找回密码、刷新 Token 和医生首次强制改密流程。失效后重新登录。 |
| 排班查询 | 服务端完整状态目录，默认展示当前日期起的范围；旧浏览器草稿缓存不是目录数据源。 |
| 目录有排班但患者查不到 | 草稿、取消出诊、已满、已截止等排班/号源不会作为可约结果；检查日期和发布状态。 |
| 科室没有医生或诊室 | 管理员先补齐启用资源。医生账号需要绑定启用档案。 |
| 排班冲突 | 检查同一医生或诊室该日的时间重叠；批量冲突会指出日期且整批回滚。 |
| 取消出诊被拒绝 | 可能已经开诊，或存在待确认/已确认预约。当前不支持替患者自动退约。 |
| 无法签到 | 检查预约已确认、就诊日期、签到窗口和是否已经签到；数据库时间是最终依据。 |
| 无法开始接诊 | 检查时段已经开始、接诊仍待就诊、本人没有其他就诊中患者。 |
| 病历版本冲突 | 保留当前输入，核对其他页面保存结果，再决定重载或重新编辑。 |
| 处方草稿阻止完成接诊 | 先提交并生成账单，或明确放弃草稿；不能删除重建来绕过版本检查。 |
| 药品已停用/处方版本冲突 | 更新目录选择或核对其它页面；错误时保留的输入不会自动保存，重新加载会覆盖未保存修改。 |
| 已提交处方尚未缴费 | 可以先完成接诊，缴费状态单独表达；本版本缴费只作模拟登记。 |
| 完成后预约仍为 BOOKED | 正常；实际就诊状态在 Encounter 中，不能据预约状态统计完成就诊量。 |
| 患者尚看不到病历 | 医生仍未完成接诊；只有完成后的病历正文可向所属患者账号返回。 |
| 404 / 403 | 越权对象详情按 404 处理；角色不匹配为 403。未签到时尚无接诊记录的 404 由患者弹窗作为正常情况处理。 |
| 401 / 登录失效 | 重新登录；账号停用、角色或 Token 版本变化也会使登录失效。 |
| 网络失败或超时 | 查询结果后再决定重试，特别是批量排班；预约创建继续使用原幂等键。 |
| 统计与后续范围 | 当前包含药品、处方、模拟收费及三图；真实支付/退款、库存、医保、通知改约、补叫、病历修订、Redis/MQ继续暂缓。 |

正常使用应用不需要 Node.js。运行前端自动测试时，需要支持 `node:test` 的 Node.js；项目根目录执行：

```powershell
node --test tools/test-frontend-api.cjs tools/test-frontend-dashboard.cjs tools/test-frontend-workflows.cjs tools/test-frontend-clinical.cjs tools/test-frontend-business.cjs
```

测试使用 Node 内置 `test`、`assert` 和 `vm` 直接执行模块源码，无需 npm 安装。覆盖 API 请求契约、JWT/错误/重试、真实首页口径、表单提交和异步竞态；新增模块检查药品价格/版本、处方防重与冲突保留、草稿放弃、模拟缴费和统计空0/日期/旧响应。DOM 模拟不验证真实 CSS 布局，也不代替 MySQL 并发或真实浏览器验收。

后端普通测试和本轮专项复现入口：

```powershell
.\mvnw.cmd test
.\tools\test-confirmation.ps1 -TestSelection 'EncounterConcurrencyMySqlIT,ScheduleManagementMySqlIT'
.\tools\test-clinical-http.ps1
```

MySQL 脚本需要本机 MySQL 8.4 原生工具，默认路径见脚本参数。脚本准备独立临时数据库和虚构数据；不要把专项连接指向正常业务库。普通单测、真实并发测试和 HTTP 联调分别提供不同证据，不能互相替代。
