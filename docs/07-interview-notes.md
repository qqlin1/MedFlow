# 项目复述与面试边界

先按 [学习清单](LEARNING_CHECKLIST.md)亲自操作和解释，再写简历。可描述为：“在原有Spring Boot单院门诊项目上，参考尚医通的预约页面流程与OpenEMR的预约/就诊边界，增量实现排班、患者预约确认、签到、医生病历及历史查询，重点处理幂等、MySQL条件扣减与事务、状态历史和归属权限。”

药品/账单只能叫简版模拟；Redis亮点只写医生详情缓存及实际故障验证；没有真实支付、医院上线、跨院EHR、FHIR、MQ或微服务就不要写这些能力。

复述顺序：

1. 讲一个患者从科室、医生到预约的动作，指出账号/就诊人/医生档案不同。
2. 讲创建预约一个事务保护哪四个事实：幂等结果、号源、预约、历史。
3. 用最后一号竞争解释条件UPDATE/唯一约束/锁顺序，不笼统说“加事务就不会超卖”。
4. 讲确认、取消、超时、签到竞争和回补一次；完成接诊为什么不退号。
5. 讲医生对象权限、病历版本、完成只读及跨医生历史的读取边界。
6. 讲一次Redis miss/hit/afterCommit失效/停机降级，承认一致性窗口。
7. 打开真实测试日志和自己点击的截图，区分单测、真实MySQL、HTTP、浏览器。

讲性能时必须给条件。现有容量实验500不同就诊人/同owner/50名额/32连接，不是线上QPS；真实结果以报告为准。用“做过什么、如何验证、边界是什么”回答追问，不编造生产责任。

最终自测问题在学习清单末尾；简历应只包含当前台账里已实现且确实验证的部分。
