业务口径已经确认：患者自己确认预约、自己签到。管理员配置科室/诊室/医生/排班；医生只处理分配给自己的接诊，历史读取有归属门禁。手册旧文中的管理员审核/拒绝预约不作为需求。
现有模型：创建预约占位，确认不重复扣容量，取消/未确认超时才按规则释放；Appointment 和 Encounter 分离，完成接诊后预约仍可为 BOOKED。只用虚构演示数据；药品/处方/缴费是简版模拟。不要把项目说成真实医院上线、微服务、真实支付或完整EHR。Java/前端版本以 pom 和源码为准。

教学规则：
- 先让我手动体验，再讲一条真实请求的 页面→API→Controller→Service→Mapper/SQL→数据库约束→响应。
- 每轮只讲一个纵向动作，最多安排约30–45分钟；不要一次讲完整个项目或大段罗列八股。
- 展示相关源码的完整关键方法/新增练习代码，再按“目的→数据和调用流程→关键机制→失败边界”解释，不一行一行碎讲，不让关键步骤躲在框架封装后面。
- 每轮给我：页面点击步骤、预期结果、真实文件与行号、一个成功例子、一个失败例子、3个复述问题、一个小练习。页面未交付时明确说明，不编造按钮。
- 特别追问：patient owner校验、JWT角色与对象权限、幂等键/request_hash、MySQL条件扣减、事务回滚、锁顺序、重复取消、签到竞争、病历版本、历史读取、afterCommit删缓存、Redis降级。
- 我说“懂了”不算通过；让我用自己的话说明规则，并指出代码位置。答错先定位误区，再用当前例子解释。
- 只读操作可自主执行；写入/停服务/更改配置由我在明确操作练习中亲自完成。不要展示.env中的密钥、JWT或密码散列。
- 结束时在回复里给“已掌握/未掌握/下次继续点”，不要擅自写入项目学习记录。能写进简历的能力必须有真实代码与测试证据。

现在先确认项目当前状态，用不超过10句话介绍业务地图；然后只开始第一课：三角色菜单、账号与医生档案/就诊人的区别，让我亲自跑一条患者预约路径。先给我点击任务，等我反馈后再深入鉴权和事务源码。
