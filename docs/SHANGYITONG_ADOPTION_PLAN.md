## B01 完整确认摘要与统一预约凭证

用户故事：患者选家人挂号后，能在提交前、成功后和列表详情中认出同一位患者、医生、日期、时段、诊室，并知道下一步做什么。

实现边界：

- 改原`app.js openBooking/renderBookingSuccess/openAppointment`的呈现，复用`clinical.js`已有可读就诊信息和`AppointmentVisitInfo`，不重建预约状态机。
- 核对摘要展示就诊人、关系与脱敏电话、医生/职称、科室/诊室、日期和时段、确认及取消截止。号源ID和数据库ID降到辅助位置；未做挂号费就不显示虚构金额。
- 详情保留预约状态、接诊状态、账单状态三个独立标签。下一步是基于事实推导的读视图，不新增覆盖所有对象的全局数据库状态。
- 待确认提示自确认；未到签到窗口展示窗口；可签到时给入口；已签到待叫号；就诊中等待医生；完成后看病历，若有待缴账单另给缴费入口。已过窗口未签到要明确提示，不误标为未确认超时EXPIRED。
- 复用现有`GET /appointments/{id}/visit-info`；若需扩展账单摘要，在已有读合同中明确可见范围，保持owner校验。写操作继续沿用原API及截止校验。

验收：

- [ ] 本人和家属各约一次，提交摘要、成功页、详情与医生名单指向同一个patientId和slot。
- [ ] 从成功页、列表详情、“就诊与病历”进入均显示同一位医生和同一诊室时间。
- [ ] 未来预约只显示窗口，不出现可成功签到的承诺；合法签到重复点击只创建一条Encounter。
- [ ] 接诊完成但药费未付同时展示两项事实；缴费不改接诊完成时间。
- [ ] 网络失败显示重试，不能伪装成预约不存在；成功但刷新失败仍保留成功结果和原幂等键。

## B02 日期可约摘要与日期优先

用户故事：患者想看内科明天谁能接诊，不必先猜一个医生再逐日试号；找指定医生时仍可先选医生。

已写入源码的接口：`GET /api/v1/patient/availability-days?departmentId=&doctorId=&from=YYYY-MM-DD&days=7`，默认数据库当天起7天、最多14天；doctor指定时必须属于所选启用科室，身份仍PATIENT。返回日期、可约时段数、有效剩余容量、去重医生数和显示状态。另有`GET /api/v1/patient/available-doctors?departmentId=&workDate=`提供当天可约医生及简介。运行验证尚未进行。

读查询规则：

- 从现有PUBLISHED排班和slot按天聚合，使用数据库时间过滤截止与可约状态；未发布、取消、关闭科室/医生不能贡献可约量。
- 区分无排班、已约满、已停止预约、有余量；如需展示未来尚未开放，必须先有实际放号规则，不为模仿参考页面伪造倒计时。
- 不用某页12个slot的余量求全天总量；如果展示医生数，按doctorId去重，同医生上午下午不计两人。
- 查询是当时快照，提交仍以原事务条件扣减为准，不缓存成保证成功的容量。
- 按科室可先选日期看该日医生；找医生入口保持医生→日期；换上游清旧slot，保留现有请求ticket和会话保护。

验收：

- [ ] 准备无排班、全部约满、有余号、全部过截止四种日期，日期卡与展开的时段符合实际。
- [ ] 同医生上午下午两班仍只计一位医生；跨分页不漏余量。
- [ ] 同科室两医生按日期可比较；指定医生查询不会混入他人。
- [ ] 取消后刷新摘要回升一次；两个患者看到最后1个号时仍只有一个提交成功。
- [ ] 快速切日期/医生，迟到响应不覆盖当前选择；摘要加载失败可重试。

## B03 轻量复诊关联

用户故事：患者从一次已完成病历点“基于本次再次预约”，医生在新接诊里能看出来源，但两次诊疗和费用独立。

已写入源码的数据与接口：

- 在新预约增加可空`source_encounter_id`作为前次接诊关联；不冗余visitType，避免来源字段与类型互相矛盾。使用新增V15 Flyway迁移文件，不改旧迁移checksum，本轮未执行迁移。
- 创建预约请求可选传来源接诊ID，仍传patientId、slotId和原Idempotency-Key。新字段必须加入request_hash；同key换来源也应冲突。
- 服务端校验来源为本人名下**同一patientId**的已完成接诊，不能给家人借用来源，也不能从草稿/进行中/不存在的接诊发起。
- 原医生/科室仅预选，可在允许目录内另选可约医生；仍走普通余量、截止、确认、自签到流程，不自动占号或生成处方。
- 新预约签到后创建新的Encounter，新病历为空；医生可只读查看来源病历。旧病历不重开、不复制诊断为新诊断。

验收：

- [ ] 从已完成记录发起，选择新日期后得到新预约ID和新接诊ID，历史有两次记录及来源标识。
- [ ] 两次病历、处方与账单各自独立；新接诊保存不改变旧正文。
- [ ] 其他账号、同账号另一个家属、未完成接诊作为来源均失败。
- [ ] 同key同来源重试一条预约；同key换来源冲突；原slot约满仍正常失败。
- [ ] 未带来源的普通预约继续可用，旧数据无来源时不伪造“初诊”或“复诊”结论。

## B04 预约历史快照

用户故事：预约之后医生或科室更名，过去单据仍能表达当时所约信息。

边界：在创建预约事务内保存必要的医生名、科室名、诊室名等快照；公开简介仍读当前目录，病历正文和处方已有冻结规则继续沿用。快照记录的是“预约时”，不宣称自动等于最终实际出诊安排。

旧数据：没有真实旧值就保持空并使用有说明的当前资料回退，不能拿今天的名称回填后宣称是当年快照。未来若允许已预约换医生/诊室，须另有变更记录；本任务不偷偷增加改约。

验收：

- [ ] 新预约后管理员改名，旧预约保留预约时信息，新预约使用新信息。
- [ ] 旧记录无快照有明确回退说明；不会出现null/undefined。
- [ ] 改药价不改变已提交处方和旧账单；患者和医生历史入口对同一条记录显示一致。
